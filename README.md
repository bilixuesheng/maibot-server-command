# 服务器命令执行

这是一个面向 MaiBot 1.x / `maibot-plugin-sdk` 2.x 的 Tool 插件。它向 Maisaka
提供 `run_server_command` 和 `send_server_file_to_qq`：前者让 MaiBot 在低权限
沙箱中运行 Ubuntu 命令并提供可选 ROOT 模式，后者把经过安全检查的服务器普通
文件发送到指定 QQ 会话。

> **兼容性说明：本插件目前仅在 Ubuntu 上测试过，其他 Linux 发行版及操作系统
> 未经测试，不保证能够正常运行。**

## 使用前必须安装

使用插件前，请先在 Ubuntu 服务器执行：

```bash
sudo apt update
sudo apt install bubblewrap
```

> 如果未安装 Bubblewrap，低权限沙箱模式无法运行命令。

版本 1.0.14 新增受管临时文件生命周期。开启后，每个临时任务会获得
`$MAIBOT_TEMP_DIR`，实际位于
`maibot-command-file/.maibot-temp/task-<随机ID>/`。同一条用户消息触发的连续
命令自动复用同一目录；运行时没有消息 ID 时，同一会话在 30 分钟空闲租约内复用。
工具返回 `temp_task_id`，模型也可在后续命令中显式续用，或通过
`start_new_temp_task=true` 开始新任务。临时目录默认保留 24 小时；插件加载时及
每小时安全清理过期、非活动任务。QQ 明确返回发送成功后，只会删除来源于受管临时
目录且身份未变化的那个源文件；失败、结果不确定、任务仍活动或文件变化时一律保留。
普通 `/work`、`/root`、`/etc` 等目录永不被该机制自动删除。

版本 1.0.13 新增 QQ 文件上传工具，默认关闭。低权限模式只能上传
`maibot-command-file`（沙箱内 `/work`）中的普通文件；受限 ROOT 与完全 ROOT
生效后可以读取全系统普通文件。所有模式都拒绝已识别的密码、Token、私钥、
Cookie、认证配置、数据库、备份等敏感文件，并拒绝符号链接、硬链接、特殊文件、
读取期间变化的文件和超限文件。目标可按 MaiBot 聊天流 ID、QQ群号或 QQ 用户号
指定；多机器人账号匹配时必须填写 `account_id`，插件不会猜测。

此版本还给受限 ROOT 增加第四次确认：“允许访问全部文件，并确认服务器没有敏感
文件”。升级后该项默认关闭，原本启用的 ROOT 会自动退回低权限沙箱，必须由管理员
重新确认。完全 ROOT 仍须先让受限 ROOT 生效；它只关闭命令正则拦截，**不会关闭
文件上传的敏感信息防护**。

版本 1.0.12 修复了 ROOT 命令超时后，使用 `setsid` 脱离原进程组的后台后代进程
仍可能存活的问题。两种 ROOT 现在都由独立子进程监督器运行：命令正常结束或超时
时，监督器会冻结、终止并回收本次命令直接产生的剩余后代进程。此版本同时纠正了
旧说明中“ROOT 仍受进程数上限限制”的错误：Linux 不对实际 UID 0 执行
`RLIMIT_NPROC`，因此“低权限沙箱最大进程数”只用于低权限模式，ROOT 不再虚假
宣称受该配置限制。

版本 1.0.11 将 ROOT 权限拆分为两层：原模式改名为“受限 ROOT”，继续使用高风险
命令正则拦截；新增“完全 ROOT”，只有受限 ROOT 已生效且十项认证全部匹配时才能
解锁，解锁后不执行高风险命令正则拦截。两种 ROOT 均默认关闭。此版本还按商店
审核建议加强了混淆命令风险说明，并在联网开关中明确提醒 localhost、内网和云
元数据端点风险。

版本 1.0.10 将插件展示名称改为“服务器命令执行”，更新项目简介与 GitHub
仓库地址。权限、沙箱和 ROOT 模式逻辑均未改变。

版本 1.0.9 使用 `assets/icon.png` 作为 WebUI 插件图标，并保留 `terminal`
作为本地图标加载失败时的备用图标。命令权限、沙箱和 ROOT 模式逻辑均未改变。

版本 1.0.8 新增需要五重条件才能生效的可选 ROOT 最高权限模式：MaiBot 必须由
root 用户运行，并同时满足总开关、三次确认开关和最终数值 `1`。生效后命令不再
进入 Bubblewrap，而是以 root 在 `/root` 中运行。工具说明和每次返回结果都会
明确告诉麦麦当前拥有服务器最高权限，并要求它坚决拒绝高风险命令；插件还会在
Bash 启动前拦截已识别的破坏性磁盘操作、递归删除、关机重启、账号/防火墙变更、
敏感凭据访问及下载后直接执行等明显高风险类别。

ROOT 模式默认关闭。任一确认条件不满足，插件都会继续使用原来的低权限沙箱。
文字提醒和规则匹配无法识别所有经过混淆的危险 Shell 命令，因此 ROOT 模式仍然
属于极高风险能力，只应在管理员明确理解后使用。

版本 1.0.7 修复了 MaiBot 以 root 启动时所有命令均报
`bwrap: Can't chdir to /work: Permission denied` 的问题。Bubblewrap 先在隔离
环境的 `/` 中完成初始化，Ubuntu 自带的 `setpriv` 随后强制切换到
`nobody:nogroup`，低权限包装器成为 `0700` 沙箱目录的所有者后才进入 `/work`
并执行麦麦提供的 Bash 命令。无需放宽目录权限，也不会把 root 权限交给命令。

1.0.6 对服务器禁止普通用户 UID 映射的兼容修复仍然保留：root 仅用于建立
Bubblewrap 的挂载和进程隔离；命令不依赖用户命名空间或 UID 映射，并会清空
附加组、capabilities 与提权能力。文件系统安全边界不变。

命令的宿主机持久化读写范围固定为：

```text
<MaiBot 主程序目录>/maibot-command-file/
```

低权限模式不接受自定义工作目录，也不会在隔离失败时回退到普通
`subprocess`。绝对路径、`..`、Shell 重定向、管道和子 Shell 不靠字符串黑名单
判断，而是由 Linux 挂载命名空间限制：MaiBot 主程序及宿主机其他数据目录根本
不会被挂载进命令环境。

## 安装

要求：

- Ubuntu
- MaiBot 1.0.8 或更高的 1.x 版本
- `maibot-plugin-sdk` 2.x
- Bubblewrap
- util-linux（Ubuntu 默认自带，用于 `/usr/bin/setpriv`）
- QQ 文件上传需要支持文件消息段的 NapCat Adapter；建议使用 1.3.2 或更高版本

将整个插件目录放入：

```text
<MaiBot>/plugins/maibot-server-command/
```

最终至少应有：

```text
<MaiBot>/plugins/maibot-server-command/
├── _manifest.json
├── assets/
│   └── icon.png
├── executor.py
├── file_upload.py
├── temp_cleanup.py
├── plugin.py
└── README.md
```

启动或重载 MaiBot。Runner 会根据插件的 `config_model` 自动生成
`config.toml`，插件还会自动创建
`<MaiBot>/maibot-command-file/`。MaiBot 可以由 root 启动。插件让受信任的
Bubblewrap 以 root 建立挂载、PID、IPC 和 UTS 隔离，然后在执行 Bash 前通过
`/usr/bin/setpriv` 清空附加组，并不可逆地降权到 Ubuntu 自带的
`nobody:nogroup`（通常为 UID/GID 65534）；命令不会继承 root 权限。沙箱目录
及其中已有内容会被安全检查后转交给该低权限用户，目录权限固定为 `0700`。即使
MaiBot 安装在 `/root` 下，插件也通过预先打开的目录句柄挂载沙箱，不会向命令
开放 `/root`。

## 低权限沙箱安全边界

- 使用 Bubblewrap 的挂载、PID、IPC、UTS、cgroup 和网络命名空间。普通用户
  启动 MaiBot 时还使用用户命名空间；root 启动模式无需用户命名空间或 UID 映射。
- 唯一映射到宿主机的可写目录是 `maibot-command-file`，在命令环境中显示为
  `/work`，并固定作为当前目录。
- `/usr/bin`、`/usr/sbin`、`/usr/lib` 和 `/usr/share` 只读挂载，以便使用
  Ubuntu 自带命令；`/usr/local`、`/etc`、`/home`、MaiBot 主程序等均不挂载。
- 联网默认关闭，此时网络命名空间不包含宿主机网络接口。
- 开启联网后，命令共享宿主机网络，可访问公网、内网以及宿主机本机监听的服务；
  也可访问云元数据地址（例如 `169.254.169.254`）。文件系统隔离、命令降权和
  资源限制仍然保持不变。
- 清空继承环境，只设置最小 `PATH`、`HOME` 和 `LANG`。
- 丢弃 Linux capabilities 并启用 `no_new_privs`；普通用户模式还会禁止嵌套
  创建用户命名空间。
- 当 MaiBot 以 root 启动时，只有受信任的 Bubblewrap 建立隔离阶段保留必要
  权限；它启动的固定 `setpriv` 包装器会在 Bash 解析命令前切换到
  `nobody:nogroup`、清空附加组及全部 capabilities。任何一步失败，命令都不会
  执行。
- 设置运行时间、输出、虚拟内存、单文件大小、文件描述符及低权限用户进程数限制。
- 执行前拒绝沙箱内已有的硬链接、FIFO、Socket 和设备文件，避免借预置对象触达
  沙箱外资源。
- 沙箱内允许普通符号链接；链接仍在 Bubblewrap 的挂载命名空间内解析，不能借此
  访问没有挂载进沙箱的宿主机路径。

需要注意：命令可以自由删除或覆盖 `maibot-command-file` **内部**的数据，这正是
该插件授权给模型的沙箱范围。重要数据不要放入该目录。虽然插件支持由 root 启动
MaiBot，但这只解决本插件命令的降权与隔离；其他插件仍会继承 MaiBot 主进程权限。
管理员应对服务器做常规备份和磁盘配额。

## 受管临时文件

开启“受管临时目录”后，模型运行命令时会得到环境变量：

```bash
$MAIBOT_TEMP_DIR
```

短期下载、转换、压缩和中间结果应写入该目录。需要长期保留的成果必须移到普通
`/work` 或由管理员明确指定的持久位置；插件不会根据模型的主观判断删除其他路径。

任务复用规则：

- 同一条触发消息中的多次命令自动复用同一个任务目录。
- 如果 Runner 没有提供原始消息 ID，则同一 `stream_id` 在 30 分钟空闲租约内复用。
- 工具结果返回 `temp_task_id`；跨消息继续同一任务时应显式传回该 ID。
- 明确开始新任务时使用 `start_new_temp_task=true`，此时不能同时传
  `temp_task_id`。
- 低权限沙箱任务与 ROOT 任务的目录所有者不同，`temp_task_id` 不能跨权限模式
  复用，避免 ROOT 生成内容在降权后被意外继承。
- 插件重载后仍可按返回的 `temp_task_id` 安全重新打开未过期目录，但目录所有者、
  权限、挂载状态或路径身份有变化时会拒绝复用。

清理规则：

- 默认保留 24 小时，可配置为 1–720 小时。插件加载时检查一次，之后每小时检查；
  因此实际删除可能比设定时间晚不到一小时。
- 正在被一条或多条并发命令使用的任务通过引用计数保护，绝不参与定时清理。
- QQ 发送只有收到明确的 `success=true` 才算成功。返回 `false`、`None`、异常或
  未知结构都视为失败或结果不确定，源文件保留且禁止自动重试。
- 发送成功后只重新打开并核对原文件的设备号、inode、类型、链接数、大小、修改
  时间和状态变更时间；全部一致才删除。目录中其他文件不会被连带删除，空目录才会
  逐级收起；最上层任务目录会保留到过期清理，保证后续命令仍获得同一路径。
- 定时清理只识别 `.maibot-temp/task-<32位随机十六进制>/`。不跟随符号链接，
  不进入挂载点；陌生命名、路径替换、权限异常和跨设备目录一律跳过。
- 单轮最多处理 128 个过期任务和 10000 个目录项，递归深度最多 64 层，避免异常
  目录拖住 MaiBot。超出预算的内容留到下一轮。
- ROOT 模式只改变命令权限，不扩大自动删除范围；受限 ROOT 和完全 ROOT 都只能
  自动清理这个专用目录。
- 关闭“受管临时目录”后不再新建、定时清理或上传后立即删除；已有临时目录会保留，
  重新开启后再按期限检查。

## QQ 文件上传

`send_server_file_to_qq` 默认关闭，必须在 WebUI 单独打开“启用 QQ 文件上传”。
只有用户明确要求把某个具体文件发送到 QQ 时，模型才可以调用；禁止主动上传、
批量探测或把不确定是否安全的文件发出。

Manifest 已按最小权限声明该工具实际使用的 `send.custom`、
`chat.get_all_streams`、`chat.get_group_streams` 和
`chat.get_private_streams` 四项 Host 能力；没有声明数据库、历史消息、主动任务或
其他无关能力。

目标类型：

- `current`：当前 QQ 会话；如果运行时没有提供当前 `stream_id`，调用会失败。
- `stream`：`target_id` 填 MaiBot 聊天流 ID。
- `group`：`target_id` 填 QQ 群号。
- `private`：`target_id` 填 QQ 用户号。
- 同一个群号或用户号由多个 QQ 机器人账号服务时，必须填写机器人
  `account_id`；插件拒绝静默选择。

`group` 和 `private` 只匹配 MaiBot 已经建立的聊天流，不会在后台擅自创建陌生
会话。文件先由插件通过安全文件描述符完整读取，再以内联文件消息交给 MaiBot 和
QQ 适配器，因此不要求 NapCat 与 MaiBot 共享同一个宿主机路径。

文件访问范围：

- 低权限沙箱：只允许相对 `/work` 的路径，或宿主机
  `maibot-command-file` 内部路径；逐级拒绝符号链接和 `..`。
- 受限 ROOT：可读取全系统普通文件。
- 完全 ROOT：同样可读取全系统普通文件；完全 ROOT 的“无正则拦截”只针对命令，
  不会扩大上传规则。

不可配置绕过的防护：

- 只允许单链接的普通文件；目录、符号链接、硬链接、FIFO、Socket、设备和空文件
  均被拒绝。
- 通过文件描述符固定读取对象，并在读取前后核对设备号、inode、链接数、大小、
  修改时间和状态变更时间；文件被替换、删除或写入时拒绝发送。
- 路径、真实路径、显示文件名和文件内容都会执行敏感信息检查。
- 明文及常见 Base64 包装会被扫描；普通 ZIP 会在不解压到磁盘的情况下检查成员
  路径和内容。加密 ZIP、嵌套压缩包、Gzip、7z、RAR、Bzip2、XZ 及已知加密
  容器因无法可靠检查而直接拒绝。
- 始终禁止密码、Token、私钥、Cookie、认证配置、数据库、备份、个人信息以及
  其他敏感数据；禁止通过改名、复制、压缩、加密或编码绕过。
- 单文件默认上限 8 MiB，可在 1–10 MiB 内配置，10 MiB 为不可突破的硬上限。
  这是按 MaiBot 插件 IPC 的 16 MiB 帧限制及 Base64 膨胀预留空间后的上限。
- 发送异常时不会自动重试；结果可能不确定，必须先人工检查 QQ 会话，以免重复。
- 发送时关闭 MaiBot 消息入库和 Maisaka 历史同步。插件请求 Host 关闭发送日志；
  当前 Host 即使输出发送预览也只显示文件组件类型，不包含 Base64、源路径或内容。
  插件审计日志也不记录源路径、文件名、文件内容或 Base64，只记录随机上传 ID、
  模式、大小、目标类型和清理状态。
- 如果源文件属于受管临时任务，且 QQ 明确返回成功、文件未变化、任务已停止，
  插件按配置立即删除该文件；其他来源永不触发自动删除。

路径和内容特征扫描只能发现已知格式，无法数学上证明任意文件不含敏感信息，尤其
无法可靠理解图片、PDF、Office 文档或专有二进制格式中的语义。模型的工具说明
因此明确要求：
**扫描未命中也不能上传不确定的文件**。管理员仍必须执行最小权限、文件分类和
服务器数据清理；ROOT 确认不是敏感信息检查的替代品。

## 受限 ROOT 模式

此模式默认关闭。只有下面条件全部满足才会生效：

1. MaiBot 主进程的实际用户为 root（有效 UID 为 0）。
2. 打开“关闭沙箱并启用受限 ROOT”。
3. 依次打开第一次、第二次和第三次确认。
4. 打开第四次确认，明确允许访问全部文件，并确认服务器没有密码、Token、私钥、
   Cookie、数据库、个人信息等敏感文件。
5. 将“最终确认”输入框中的 `0` 手动改为 `1`。

生效后的行为：

- 不启动 Bubblewrap，也不降权到 `nobody`。
- Bash 的实际 UID/GID 为 `0:0`，固定工作目录为 `/root`。
- 每次工具结果最前面都有“受限 ROOT”警告，并要求麦麦拒绝高风险命令。
- 日志以醒目的高危级别记录模式启用、准备执行、成功、失败和拒绝。
- 超时、输出、内存、单文件大小和文件描述符限制仍然保留。
- Linux 不对 UID 0 执行 `RLIMIT_NPROC`，因此“低权限沙箱最大进程数”配置在
ROOT 中不生效，插件不会再把它描述成 ROOT 防护。
- 命令由独立子进程监督器运行。命令正常结束或超时后，本次命令直接产生且仍然
  存活的后台后代进程（包括使用 `setsid` 或双重 fork 的进程）会被清理和回收。
- 插件在执行前拒绝已识别的明显高风险类别，且不会把原始命令或 Token 写入日志。

规则匹配只是一层额外防护，不能安全理解任意 Bash、脚本语言或混淆命令。
Base64 编码、变量展开、`eval`、动态拼接及其他间接执行方式都可能绕过规则；
“未被拦截”绝不代表命令安全。ROOT 进程理论上能够读取、修改或删除服务器上的
任何数据，也能访问网络和本机服务；管理员必须自行做好备份、最小化服务器凭据，
并只在必要时短期开启。

受限 ROOT 的全文件访问同样适用于 QQ 文件上传，但上传工具仍会拒绝已识别的敏感
文件。命令工具和上传工具是两条不同的数据通路：命令正则是否命中不会改变上传
工具的路径、文件类型、竞态和敏感内容检查。

## 完全 ROOT 模式

此模式默认关闭，而且不能绕过受限 ROOT 直接开启。必须先让受限 ROOT 真正生效，
再打开“申请解锁完全 ROOT”，并让十项认证严格匹配：

1. 认证 1～5 全部开启。
2. 认证 6 关闭。
3. 认证 7 开启。
4. 认证 8 关闭。
5. 认证 9 从 `1` 改成 `0`。
6. 认证 10 从 `true` 改成 `false`。

完全 ROOT 生效后仍以 UID/GID `0:0` 在 `/root` 运行，但插件不会调用高风险命令
正则进行拒绝。工具返回与日志会明确显示 `root_unrestricted` 和
`regex_guard=disabled`。命令超时、输出截断、虚拟内存、文件大小及文件描述符
上限仍作为工具运行的操作性边界保留，但不会限制 Bash 能尝试哪一种 ROOT 操作。
UID 0 不受配置中的进程数上限约束；命令结束或超时后，监督器会清理本次命令直接
产生的剩余后台后代进程。要启动长期系统服务，应通过 systemd 等系统服务管理器
明确创建，而不是依靠脱离工具调用的孤儿进程。

完全 ROOT 能执行受限 ROOT 会拒绝的递归删除、磁盘操作、系统账号或服务变更等
命令，也能读取凭据和访问所有宿主机网络。十重认证只是防误触，不会降低生效后的
权限和破坏能力。文件上传不继承“无命令正则拦截”：敏感文件仍然不能发送。

## 配置

首次加载后，MaiBot 会根据 `config_model` 生成 `config.toml`。可在 WebUI 调整：

- 是否启用工具
- 是否允许命令联网（默认关闭）
- 单次命令超时
- 输出保留上限
- 每进程虚拟内存上限
- 单文件大小上限
- 低权限沙箱进程数上限（两种 ROOT 不应用此项）
- QQ 文件上传总开关（默认关闭）
- QQ 单文件上传上限（默认 8 MiB，硬上限 10 MiB）
- 受管临时目录总开关（默认开启）
- 临时任务保留时长（默认 24 小时）
- QQ 明确发送成功后立即删除临时源文件（默认开启）
- 受限 ROOT 总开关
- 第一次、第二次、第三次和第四次确认开关
- 最终数字确认输入框
- 完全 ROOT 总开关及十项认证

WebUI 中会显示“启用命令工具”“允许命令联网”“命令超时时间（秒）”等中文
名称，并在每项下面显示中文说明。运行时 `config.toml` 不随仓库分发，避免安装
或升级时覆盖用户设置；它会在首次加载后由 Runner 根据中文配置模型生成。

代码中另有不可由配置突破的硬上限。

要允许麦麦使用 `curl`、`wget` 等联网命令，请在 WebUI 打开“是否允许沙箱命令
访问网络”，或在插件配置中设置：

```toml
[plugin]
config_version = "1.0.14"

[sandbox]
network_enabled = true
```

保存配置后，日志会显示 `network_enabled=True`。开启联网等于授权麦麦访问公网、
服务器内网以及本机网络服务，也允许它上传沙箱内的数据；请不要把密码、Token 或
其他敏感文件放进 `maibot-command-file`。

开启 QQ 文件上传：

```toml
[file_upload]
enabled = true
max_upload_mb = 8
```

该开关不会自动开启 ROOT。ROOT 未生效时，即使上传开关已打开，也只能读取
`maibot-command-file`。要使用 QQ 群号或 QQ 用户号指定目标，目标必须已经在
MaiBot 中建立聊天流；多机器人账号环境还应显式传入 `account_id`。

受管临时文件的默认配置：

```toml
[temp_cleanup]
enabled = true
retention_hours = 24
delete_after_upload = true
```

关闭后，命令仍可使用普通 `/work`，但不会获得 `$MAIBOT_TEMP_DIR`，插件也不会
定时删除或在 QQ 发送成功后删除任何源文件。

受限 ROOT 的完整配置如下。请注意：下列值全部匹配会关闭命令沙箱。

```toml
[root_mode]
enabled = true
confirmation_1 = true
confirmation_2 = true
confirmation_3 = true
confirmation_4 = true
final_confirmation = 1
```

完全 ROOT 的配置如下；它只有在上面的受限 ROOT 已生效时才可能启用：

```toml
[unrestricted_root]
enabled = true
confirmation_1 = true
confirmation_2 = true
confirmation_3 = true
confirmation_4 = true
confirmation_5 = true
confirmation_6 = false
confirmation_7 = true
confirmation_8 = false
confirmation_9 = 0
confirmation_10 = false
```

如果 MaiBot 不是 root，受限 ROOT 未生效，或任一认证值不匹配，日志会说明未生效
原因。要彻底关闭 ROOT 权限，把 `[root_mode].enabled` 和
`[unrestricted_root].enabled` 都改回 `false`。

## 部署后检查

安装插件后，可让 MaiBot 执行：

```bash
pwd
printf 'hello\n' > hello.txt
ls -la
```

预期工作目录为 `/work`，文件会出现在
`<MaiBot>/maibot-command-file/hello.txt`。再执行 `ls /etc` 应显示路径不存在；
在默认配置下联网命令应失败。

开启 `network_enabled` 后，可测试：

```bash
curl -I --max-time 10 https://example.com
```

麦麦会收到退出码、标准输出、标准错误、是否超时和输出是否被截断。服务器日志会
记录命令开始、成功、非零退出、超时或沙箱异常；日志只记录命令摘要 ID，不记录
完整命令，避免将命令中的密码或 Token 写入日志。
